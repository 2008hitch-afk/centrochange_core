## Implemented behavior and migration

`CC Unpaid Threshold` is an immutable Management-configured revision per professional, with an explicit integer N >= 0, unique payload-bound request key and serialized revision sequence. Zero is valid; missing/negative/fractional/boolean/out-of-storage-range values are rejected, never coerced into a default. A missing threshold blocks final capture even when the source is already paid; the configuration exception must be resolved explicitly. The professional threshold is independent of the patient and is counted separately for each patient/professional pair across centers. Peer session identifiers in exposed snapshots/queue/position facts are restricted to the source center; global count/rank do not grant access to another center’s identities or positions. Native signed Int storage admits up to 2,147,483,647.

Performed unpaid native appointments are ordered deterministically by session date/time/canonical identity. First N mature the explicitly configured fixed/percentage expected amount; subsequent positions are SUSPENDED with amount_known=false and null amount in service projections, not permanent zero compensation. Paid sessions do not consume unpaid capacity. Native submitted invoice outstanding is authoritative when billed; otherwise current audited operational settlement is used. An override does not remove its still-unpaid session from this count.

Expectations append per-session revisions, linked to their predecessor, with immutable original paid/threshold/rank/count/source/rule facts. The current projection uses sequence, with creation/name ordering retained for legacy sequence-zero rows. Replay compares the current semantic state (including native Currency storage's unknown-value representation), so retries do not append duplicate snapshots and a return to an earlier state appends a new revision rather than accidentally returning an obsolete historical record.

Native Sales Invoice/Payment Entry post-submit/cancel hooks reevaluate affected-center positions after native outstanding updates. Existing administrative refresh/scheduled catch-up reevaluates current expectations, covering operational settlement changes and configuration updates without a separate ledger or new scheduler. Threshold changes append configuration and expectation revisions without rewriting original facts. One existing Professional Expectation Review condition per source session updates/reopens/closes deterministically and exposes patient, professional, session, applied threshold, unpaid count/rank and compensation/resolution state. Management-only override requires the current suspended snapshot; the append-only audit records actor, timestamp, reason, source session and before/after states. Its unpaid/original facts and historical suspended snapshot remain intact.

Supported schema migration adds one product DocType (977 total), expectation fields/state and queue details. It records DECISION-054 as the fixed authoritative policy in Finance Settings; generic configuration cannot select a superseded binary policy. No existing threshold is fabricated. Native Purchase Invoice comparison, GL and accounting settlement remain separate.

Changed areas: product DocTypes/settings, professional economics, administrative queue, supported native hooks/migration, scoped reporting/current projection, finance UI and targeted fixture/harness coverage. No upstream edits, new production/provider dependencies or persistent manual container patches.
