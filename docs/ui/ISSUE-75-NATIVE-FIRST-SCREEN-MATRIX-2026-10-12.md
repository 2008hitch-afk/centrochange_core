## Meccanismi supportati e pin

- Frappe/ERPNext `16.50.0`, Healthcare `16.6.1`, Builder `1.35.1` sul solo `centrochange-dev`.
- La [documentazione Frappe List View](https://docs.frappe.io/framework/user/en/api/list) descrive `hide_name_column`, `formatters` e `onload`; il sorgente pinned `frappe/desk/form/meta.py` carica `doctype_list_js` e `frappe/public/js/frappe/list/base_list.js` usa `in_standard_filter` per i filtri rapidi.
- Le [traduzioni delle app](https://docs.frappe.io/framework/user/en/guides/basics/translations) risiedono in `translations/it.csv`; gli [hook Desk](https://docs.frappe.io/framework/user/en/python-api/hooks) caricano gli asset versionati.
- Le [customizzazioni esportabili](https://docs.frappe.io/framework/user/en/guides/app-development/exporting-customizations) sostituiscono tutti i Property Setter/Custom DocPerm esportati sul Site; per il solo `department.in_standard_filter` si usa una patch idempotente e circoscritta, senza esportare l'intero set permessi.

La sidebar Centro Change resta un adattatore circoscritto caricato dal hook Desk: la navigazione nativa Workspace v16 è organizzata per modulo, mentre questo percorso deve restare unico su Page operative e List/Form ERPNext di più moduli, con menu per ruolo. La shell cliente non carica più Tabler Core né riscrive il testo delle viste native nel DOM. Un observer controlla solo la sostituzione del figlio diretto del `body`; le transizioni ordinarie usano `page-change`. I file Tabler vendorizzati e l'asset web esistente sono conservati per le pagine website/login già operative e per regressione controllata; Tabler Icons locali restano icone, non framework di layout.
