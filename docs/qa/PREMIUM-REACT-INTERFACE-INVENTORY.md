Report storici, da non trasferire automaticamente alla HEAD o a ogni azione. `NOT_VERIFIED` = nessuna prova specifica in questo audit.

## Limiti riscontrati, senza aprire la fase di correzione

1. La PR #150 ha un commit ulteriore rispetto alla sorgente dell’immagine, ma il diff riguarda soltanto test/evidenze/report; nessuna differenza di codice applicativo. La verifica byte-per-byte dell’immagine non è stata ripetuta in AUDIT-00. `cc_premium_primary=0` è confermato dalla lettura read-only di configurazione, coerente con attesa Owner.
2. I 24 test live del 22/10 sono una suite, non prove di ogni pulsante/form, limite di ruolo o dataset. L'audit per interfaccia deve acquisire esiti con SHA, identità e fixture propri.
3. Quattro Patient sintetici storici fuori manifest hanno ID grezzi secondo `LIVE-22`; il resolver non li rinomina senza attestazione di proprietà. Non alterare ID reali o dati fiscali per soddisfare l'etichetta demo.
4. La ricerca negli 11 archivi filtra solo le pagine già caricate; non equipararla a ricerca completa server-side. Sales/Purchase/Bank detail mostra proiezioni. Verificare con l'Owner se il requisito della specifica interfaccia esige più campi o ricerca globale.
5. Creazione standalone Patient/Practitioner/Item, nuova allocazione Payment Entry e collegamento fiscale Patient↔Customer arbitrario restano **bloccati** dal perimetro DECISION-063; la presenza di `workspace.create_patient` nel backend non è autorizzazione a esporlo nella UI senza riconciliare policy.
6. DECISION-059 rinvia la correzione retroattiva dell'orario seduta (#78). Sito pubblico completo, OCR, POS/feed provider, payment links e contabilità gestionale avanzata sono fuori dal perimetro core attuale.
